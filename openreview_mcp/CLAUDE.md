# openreview_mcp/

The installable Python package. Houses the `register_knowledge_tools` public API, the data/logic layers it uses, the standalone FastMCP entry point, and the bundled static knowledge files.

## Files

- `__init__.py` — Re-exports `register_knowledge_tools` as the package's public API. Zero import side effects.
- `registration.py` — Reusable `register_knowledge_tools(mcp, knowledge_path=None, tests_path=None) -> dict[str, Callable[..., str]]`. Builds the introspection cache, the static-knowledge base, and the test-suite index at CALL time (not import time), then defines the 4 tools as closures via `@mcp.tool()` and registers them on the passed-in FastMCP instance. Returns a dict of tool handles keyed by name. Downstream consumers import this function and mount the knowledge tools onto their own FastMCP instance.
- `server.py` — Thin standalone entry point (~27 lines). Creates its own `FastMCP`, calls `register_knowledge_tools(mcp)`, provides `main()` for the `openreview-mcp` CLI script. This is the only module that does work at import time, and only because it IS the standalone CLI entry point.
- `introspection.py` — Live introspection of the installed `openreview-py` package using Python's `inspect` module. `TARGET_CLASSES` lists the (module, class) pairs to introspect; `TARGET_MODULES` lists modules whose top-level functions are introspected as pseudo-classes. Each entry is tagged with an `api_version` (`v1`/`v2`/`None`) via `_API_VERSION_BY_MODULE` so search/detail output can distinguish v1 vs v2 calls with the same name. `search_methods()` ranks by exact name > name contains > docstring contains > param contains and caps results at 15. `get_method_details()` returns exact + partial name matches.
- `knowledge.py` — Parser for the static `llm.txt`. `KnowledgeBase` is a dataclass holding `practices` (a dict keyed by `## ` section header). `search_best_practices()` ranks header matches above content matches.
- `tests_index.py` — AST-postings index over the upstream `openreview-py/tests/` directory backing the `search_test_examples` tool. `TestSnippet` records `(file, class_name, func_name, lineno range, arg_names, length_lines, tokens)` for each indexed test function. `build_test_index(tests_dir)` walks top-level `test_*.py` files, parses with `ast` only (no import), skips files importing `selenium`/`webdriver`, and builds a `postings` map from tokens (identifier names + underscore/dot/slash splits + string-literal substrings) to snippet indices. `search_test_index()` scores by query-term hits (2x in name/class, 1x in body tokens, minus a mild long-method penalty). `format_test_results()` reads bodies lazily via `linecache`, dedents, hard-caps each body at 60 lines (first 30 + elided marker + last 20), and appends a `conftest Helpers methods available: ...` footer when any rendered body references `helpers.`.
- `knowledge_files/` — Bundled `llm.txt`, synced verbatim from the upstream `openreview-py` repo. This is the default knowledge source when `OPENREVIEW_KNOWLEDGE_PATH` is unset.

## Important patterns

- **Zero import side effects in `registration.py`.** No module-level FastMCP creation, no introspection at import, no knowledge loading at import. This is load-bearing: it lets downstream packages import `register_knowledge_tools` without accidentally spinning up a server or eating the introspection cost.
- **`server.py` is the only module that does work at import time,** and only because it IS the standalone CLI entry point. Running `openreview-mcp` on the CLI is the only code path that creates a module-level FastMCP here.
- **Tool functions return plain strings.** LLMs consume the output directly, so keep formatting concise and avoid repetition.
- **`register_knowledge_tools` returns `dict[str, Callable[..., str]]`** keyed by tool name. Production code typically ignores the return value; tests use it to invoke tools directly as plain callables: `handles["search_api"](query="...")`. Note: fastmcp 3.2.2's `@mcp.tool()` decorator registers the tool internally on the `FastMCP` instance but leaves the calling-scope name as the plain function — there is no `.fn` attribute on decorated functions.
- **Knowledge path resolution priority**: explicit `knowledge_path` arg > `OPENREVIEW_KNOWLEDGE_PATH` env var > bundled `knowledge_files/` directory. All resolution happens inside `register_knowledge_tools` via `_resolve_knowledge_path`, not at module level.
- **Tests path resolution priority**: explicit `tests_path` arg > `OPENREVIEW_TESTS_PATH` env var > `{knowledge_path}/tests/` auto-detect (works when `OPENREVIEW_KNOWLEDGE_PATH` points at the repo root). Resolved inside `register_knowledge_tools` via `_resolve_tests_path`. If nothing resolves, the index is `None` and `search_test_examples` returns a clear disabled message — the other tools keep working.
- **Test-suite index is AST-only and lazy.** `build_test_index` parses each `test_*.py` exactly once at call time (no import, no execution), records line ranges + token sets, and never holds full file bodies in memory. Bodies are sliced from `linecache` at query time. Whole-build failures are caught in `register_knowledge_tools` so a broken checkout never blocks the other tools.
- **No environment variable reads at module level.** Downstream consumers can set env vars after import, or override with the explicit `knowledge_path` / `tests_path` arguments.

## When editing

- **Adding a tool**: add a new `@mcp.tool()`-decorated closure inside `register_knowledge_tools`, give it a clear `Args:` docstring (visible to the LLM), make sure it returns a string, and add it to the returned dict.
- **Adding an introspection target**: append to `TARGET_CLASSES` (for classes) or `TARGET_MODULES` (for top-level functions) in `introspection.py`. Private methods are skipped except `__init__`. If the module belongs to a specific API version, add an entry to `_API_VERSION_BY_MODULE` so results get the `[v1]`/`[v2]` tag.
- **Changing result formatting**: update `_format_search_results` or `_format_method_details` in `registration.py`. For test-snippet output, edit `format_test_results` in `tests_index.py`.
- **Tweaking the test-suite index** (tokens, ranking, truncation, stopwords): everything lives in `tests_index.py`. Token stopwords are in `_STOPWORDS`; ranking is in `search_test_index`; truncation in `_truncate_body`; the selenium import regex is `_SELENIUM_RE`. Hermetic fixtures live under `tests/fixtures/fake_tests/` — keep them in sync if you change the public output shape.
- **Updating bundled knowledge**: `cp /path/to/openreview-py/llm.txt openreview_mcp/knowledge_files/`. There is no auto-sync — this is a manual step at release time. `tests/test_bundled_knowledge.py` catches a missed sync by asserting the bundled `llm.txt` exists and parses to non-empty practice sections. The library-level call-site corpus comes from the test-suite index, not the static file, so that piece stays current automatically once the path is mounted.
